# PDF Tools · Orbitvo Tools

隐私优先的浏览器本地 PDF 页面整理工具。合并、拆分、删除、旋转、重排和轻量标注默认在当前设备中完成，原 PDF 不上传到 Orbitvo 服务器。

## 当前能力

- 合并多个 PDF，并调整文件顺序
- 提取指定页面或逐页打包为 ZIP
- 删除、旋转和重排页面
- 在页面上叠加文字与图片后导出
- 长任务显示页级进度，可随时取消；取消后原文件不变并可直接重试
- 导出文件名保留原文件身份，并用操作类型区分结果
- 可选联网翻译：只发送待翻译文字，不发送 PDF 文件
- 保存主题设置，以及最近 24 小时内的重排操作配方；不保存 PDF 内容

## 能力边界

- “编辑”是叠加文字和图片，不会改写 PDF 中原有文字。
- 翻译由 MyMemory 提供，使用前必须明确同意；扫描件不支持 OCR。
- 浏览器没有统一的文件大小上限。大文件和长文档可能受设备内存限制，应用会给出风险提示。
- 密码保护、文件损坏和设备内存不足会分别提示恢复建议；浏览器崩溃或系统强制终止仍可能中断任务。
- PDF.js 使用独立 worker 解析和渲染；页面写入由 `pdf-lib` 在主线程分段执行并主动让出响应时间，目前不承诺后台持续运行。
- 当前 P0 聚焦页面整理，不承诺压缩、OCR、电子签名、云同步或多人协作。

## 本地开发

要求 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

完整检查：

```bash
npm run check
```

生产产物输出到 `dist/`。项目使用固定版本的 `pdf-lib`、`pdfjs-dist` 和 JSZip，并将 PDF.js worker 一同构建，不依赖运行时 CDN。

## 隐私与本地数据

常规页面操作不会请求文档处理服务器。联网翻译只在用户勾选同意后调用 `api.mymemory.translated.net`。浏览器本地只保存主题和操作配方元数据，可在“隐私与限制”中清除。

## 部署准备

项目必须先执行 Vite 构建，再发布 `dist/`；不能直接把仓库源码目录作为静态站点，否则浏览器无法解析 npm 模块。GitHub Pages 工作流会在 `main` 更新后执行测试、构建并发布产物，`vercel.json` 也已声明构建目录和基础安全响应头。

仓库仍启用 GitHub Pages 的旧分支发布器，因此工作流会先等待旧发布完成，再发布并校验 Vite 产物，避免源码覆盖生产构建。若以后在仓库设置中将 Pages Source 切换为 GitHub Actions，工作流会自动跳过不存在的旧发布。

正式域名为 `pdf.orbitvo.com`，canonical、OG URL、robots 和 sitemap 统一使用该地址。迁移验收期间，旧的 `pdf.zsphere.top` 仅作为 GitHub Pages 回退入口保留；是否移除旧域名需在新域名的 DNS、TLS 与交互验收完成后决定。
